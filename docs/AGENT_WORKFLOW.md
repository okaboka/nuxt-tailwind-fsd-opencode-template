# Процесс работы агентов

Оркестрация описана в `.opencode/agents/workflow.md`. Здесь — шаблоны передачи
задач между агентами, definition of done и правила синхронизации документации.

## Процесс и оркестрация

Цикл: Planner → Workflow → утверждение пользователем → Developer → Reviewer →
исправления (если нужны) → итоговый отчёт. Только Workflow общается с
пользователем; Planner, Developer и Reviewer — subagent'ы без диалога с
пользователем. Реализация не начинается без явного утверждения плана
(approval gate).

## Неоднозначности и вопросы пользователю

Неоднозначность — ветка поведения (включая ветку ошибки и edge-case), для которой
нельзя однозначно вывести результат из исходной задачи, утверждённого плана,
`AGENTS.md`, `README.md` и существующего поведения кода. Поведение, уже
реализованное в коде и не противоречащее правилам проекта, неоднозначным не
считается. Решение, зафиксированное в утверждённом плане, повторно не
оспаривается.

- Трактовку не выбирает ни один агент, включая «минимальный», самый простой или
  «очевидный» вариант. Предположение о поведении не заменяет вопрос.
- Planner выносит неоднозначность в план как открытый вопрос (раздел
  «Open Questions»); план с открытым вопросом не готов к утверждению.
- Вопрос пользователю задаёт только Workflow: Planner, Developer и Reviewer —
  subagent'ы без диалога с пользователем. Ответ и решение фиксируются в плане.
- Ответ на вопрос не является утверждением плана: план обновляется и снова
  представляется пользователю (approval gate, см. `.opencode/agents/workflow.md`,
  PHASE 3).
- Reviewer не решает неоднозначность, не понижает её до Low/Recommendation и не
  ставит APPROVED, пока вопрос не согласован. При открытом вопросе verdict —
  BLOCKED, вопрос выносится в раздел «Open Questions» отчёта.
- Developer, обнаруживший неоднозначность во время реализации, останавливается и
  возвращает вопрос Workflow.
- Незакрытый открытый вопрос — блокирующее условие завершения задачи.

## Definition of done

### Для задачи с кодом

- Все acceptance criteria выполнены.
- План реализован полностью; изменения вне scope отсутствуют или согласованы.
- Нет `any` в новом/изменённом коде; nullability и ошибки обработаны.
- Границы FSD соблюдены; документированное исключение `entities → app` не
  нарушено и не расширено.
- Нет `index.ts` и barrel-файлов.
- Выполнены реальные проверки; неприменимые команды честно помечены.
- Независимое ревью завершено; Critical/High устранены.
- Затронутая документация обновлена.
- Открытые вопросы по неоднозначному поведению отсутствуют: каждый закрыт
  ответом пользователя и зафиксирован в плане.

### Для docs-задачи

- Упомянутые в документации пути и файлы существуют (кроме явно помеченных
  генерируемых и опциональных).
- Каждая команда существует в `package.json` либо помечена как
  отсутствующая/нерабочая.
- Нет значений секретов, `.env`-значений и учётных данных.
- Нет правил, продублированных в нескольких файлах: у темы один источник истины.
- Документация не противоречит коду и конфигурации.
- Открытые вопросы по неоднозначному поведению отсутствуют: каждый закрыт
  ответом пользователя и зафиксирован в плане.

### Для изменения конфигурации и инструментов

- JSON/YAML валиден; конфигурация opencode читается без ошибок.
- `default_agent` указывает на primary-агента (`workflow`).
- Subagent'ы `planner`, `developer`, `reviewer` описаны и корректно ограничены.
- Permissions не дают `workflow` редактировать файлы и запускать Bash; правила
  git не позволяют мутации.
- Выполнен smoke test: opencode запускается и видит конфигурацию; если CLI
  недоступен — статус NOT RUN с причиной.
- `README.md` и `AGENTS.md` обновлены и не противоречат конфигурации.
- Выполнены реальные проверки; неприменимые команды честно помечены.

## Правило doc-drift

Изменение поведения, команд, конфигурации или правил работы агентов требует
обновления соответствующего документа в том же изменении. При расхождении
приоритет определяется причиной (см. «Docs vs code»): легитимное изменение
поведения → правится документ; нарушение утверждённого контракта/инварианта →
правится код.

## Docs vs code

Docs описывают код. Если код расходится с docs, сначала определи причину:
изменение поведения (тогда правится docs) или нарушение утверждённого
контракта/инварианта (тогда правится код, а docs не подгоняются под дефект).
Если поведение изменилось намеренно, документация обновляется в том же изменении.

### Синхронизация после правок

1. Определи затронутые области по `git diff --stat` и списку изменённых файлов.
2. Сопоставь их с таблицей триггеров ниже.
3. Прочитай только затронутые разделы документации, не весь `docs/`.
4. Прави только изменившееся; документ целиком не переписывай.
5. Если расхождение неочевидно — сверься с кодом, не с памятью.
6. Не добавляй быстро устаревающие детали: перечисления компонентов, сигнатуры,
   пошаговые реализации.

| Область изменения | Документ |
| --- | --- |
| Новый компонент, слой FSD, страница, маршрут, импорт | `AGENTS.md` (правило), `README.md` (структура) |
| Новая команда, env-переменная, точка входа, зависимость | `README.md`, `package.json` |
| Изменение конфигурации Nuxt, ESLint, Vitest, TypeScript | `README.md`, `AGENTS.md` |
| Изменение процесса, handoff, definition of done | `docs/AGENT_WORKFLOW.md` |
| Изменение оркестрации, агентов, permissions | `.opencode/agents/`, `opencode.json`; ссылки в `README.md` |
| Новые запреты/инварианты проекта | `AGENTS.md`; в `README.md` — ссылка, не копия |

## Отсутствие lock-файла

`package-lock.json` в шаблоне отсутствует намеренно: зависимости не
зафиксированы, и после первого `npm install` lock-файл создастся в вашем
репозитории. Это осознанное решение, а не пропущенный артефакт. Установка
зависимостей и подготовка окружения выполняются через `npm install`.

## Единственный источник истины

| Тема | Файл |
| --- | --- |
| Расположение кода, команды, env-имена | `README.md` |
| Правила, инварианты, FSD, проверки | `AGENTS.md` |
| Процесс, handoff, definition of done | `docs/AGENT_WORKFLOW.md` |
| Оркестрация агентов | `.opencode/agents/workflow.md` |
| Конфигурация агентов и permissions | `opencode.json`, `.opencode/agents/` |
| Неоднозначности, открытые вопросы, эскалация | `docs/AGENT_WORKFLOW.md` |

При расхождении `AGENTS.md` и `docs/AGENT_WORKFLOW.md` приоритет у более
конкретного документа по теме; код авторитетен для описания текущего поведения,
но поведение, нарушающее утверждённый контракт или инвариант, — дефект; в этом
случае правится код, а не docs (см. «Docs vs code»).
